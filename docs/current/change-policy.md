# ライブラリ変更の方針

## 後方互換性より設計

個人用ライブラリなので、**後方互換性のために妥協しない**。設計・命名・API を良くできるなら、
破壊的変更（リネーム・シグネチャ変更・削除・再構成）を積極的に行う。理由は
[decisions/0002-no-backward-compatibility.md](../decisions/0002-no-backward-compatibility.md)。

破壊的変更をするときは `lib/`・`test/` から参照を洗い出し、**呼び出し側もすべて追随**させる。
古い API を中途半端に残さない。

```sh
grep -rn <old_name> lib test
```

型名の PascalCase 化のような命名の移行も、この「ついでに直して参照を追随させる」やり方で
段階的に進める（[coding-style.md](coding-style.md)）。

## 計算量を悪化させない

- リファクタでもバグ修正でも、各操作の時間計算量を既存より悪くしない。
- 可読性とトレードオフになるなら**計算量を優先**する。
- どうしても変える必要があるときは、妥当性を示して合意を取る。
- 空間計算量は実用範囲では問わないが、不要なコピー・確保は避ける。
