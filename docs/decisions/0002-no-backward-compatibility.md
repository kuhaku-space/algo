# 0002. 後方互換性のために妥協しない

## 決定

設計・命名・API を良くできるなら、破壊的変更（リネーム・シグネチャ変更・削除・再構成）を
積極的に行う。古い API を互換のために残さない。

## 理由

これは個人用ライブラリで、利用者はリポジトリ内（`lib/`・`test/`）と自分の提出コードだけ。
外部に公開された安定 API を約束していないので、互換性の維持コストを払う相手がいない。
一方で、悪い名前や API はライブラリを使うたびにコストを払わせる。

## 影響

- 破壊的変更のたびに `lib/`・`test/` から参照を洗い出し、呼び出し側もすべて追随させる。
- 型名の PascalCase 化のような移行も、一括改名ではなく「変更のついでに直して参照を追随」で進める。
- 一方で**計算量は悪化させない**という制約は残る。現行の規則は
  [current/change-policy.md](../current/change-policy.md)。
